# 章節上架、插圖與交付整理通則

本文件適用全站後續章節，配合 AI_COLLAB_WORKFLOW.md 與 SITE_SYNC_WORKFLOW.md。作者當次明確要求優先；交付包內 Prompt 是素材說明，與網站已驗收規則不一致時，先依作者指定的優先順序處理。

## 插圖位置與呈現

- 依已驗收《規矩》第一章慣例，預設集中於章名後、第一段正文前，按故事發生順序排列，各圖只出現一次。來源稿中的中段圖位視為情節對照；作者當次明確指定中段時才在指定事件附近插入，不在情節發生前後任意錯置。
- 封面與內文插圖分開；新增章節不得覆蓋作品封面。正式內文圖位於 `web/assets/illustrations/<work-id>/`，引用使用 `assets/illustrations/<work-id>/<chapter_scene>.webp`；不可引用本地歸檔或來源包。
- 沿用 HTML img、繁體 alt、實際 width/height、lazy/async 與現有閱讀器等比例 contain。完整呈現主體，不強制拉伸，不用 CSS 隱藏來源瑕疵。低解析度來源不以插值放大冒稱高解析原圖。
- 入庫時檢查四邊白線、拼圖殘邊、透明邊及比例。修圖須保存原件，記錄處理方式、輸出尺寸與雜湊；生成式修圖應檢查人物／構圖差異並明確註記，不宣稱像素不變。無需生成時沿既有壓縮流程轉 WebP，無損轉換需實測像素一致。

## 正文與註解

- 依唯一核准稿建立既有章節 ID、更新 metadata 及日期，不另建作品／索引。正文不得擅自潤稿；圖片移位、路徑及註碼格式適配要記錄。
- 來源 Markdown `[^n]` 必須轉為既有閱讀器可用的 `sup.fn-ref` 與 `section.footnotes`，保留解釋內容；不得讓原始語法直接成為讀者看到的失效註腳。
- 跨章人物、衣著、時間與金額有明顯矛盾時，先列最小修改供作者裁定；未裁定前不宣稱連續性通過，也不悄改其他章。

## 完整整理與發布

1. 盤點六類內容：正文、metadata、正式媒體、來源原件、交付說明、暫存產物；記錄 Git 既有差異。
2. 原件逐檔 SHA-256 保存到忽略的 `_archive/source-packages/`，manifest 記來源到正式路徑與衍生處理；不公開 Prompt、私人母版或原始來源包。
3. 完成章節整合後跑 check、test、build、release gate 及適用瀏覽器回歸；手機／桌面、三主題、翻頁／滾動、圖片順序／比例、註腳、繁簡與進度均需實測，未測部分明示。
4. 依同步流程檢查精確暫存樹獨立建置、既有 Pages 部署 SHA 與線上完整 Build 雜湊；Push 成功不代表發布成功。
5. 歸檔逐檔核對、確認正式 Build 無來源包依賴後，清理本次入口的重複交付物。只處理已識別檔案，不留下散落根目錄的來源包或測試圖，也不清除其他工作或歷史備份。
6. 更新接收紀錄與實作／狀態／變更文件，最後 AI_SYNC_BRIEF；回報正式路徑、歸檔、驗證、Commit／部署及未解決項目。
