# 共創規則｜《臆想書房》小說協作

> 用途：作為小說共創助手、編輯助手與 Codex/Agent 的寫作層規則。與工程層 `AGENTS.md` 共存，不取代或覆寫既有工程保護規範。
> 版本：2026-10-28 v1.1｜由《台南少年追風記》EP.05〈夢醒時分〉重寫與作者反饋整理，並增補「只補回收、不加冗詞」修稿原則。

## 1. 先區分工作模式

### A. 即興共創（接龍）
- 作者主導故事主角的重大決定、台詞及方向；如《台南少年追風記》，作者扮演**柏翰**，AI 主寫其他人物、環境和下一步情節。
- AI 接續一小段，留下可自然接話的開口；不搶寫作者尚未決定的重要回應，不擅自跳到結局。
- 可以先寫得自由、有趣，但不要每個節拍都變成「嘉豪一句／翔宇一句／柏翰一句」的固定吐槽循環。
- 作者當場修改設定或舞台順序，視為該版故事的新準則。優先順應，不辯解或過度校正。

### B. 正式整理／修稿（可供上架）
- **互動時可以放，定稿時必須剪。** 即興聊天與逐輪產出的素材不是一定要逐字搬入小說。
- 以作者最新確認的原稿為母本：先減贅字、重複反應與無功能的過場；**不要整篇推翻重寫**，除非作者明確要求。
- 一個笑點原則上**鋪陳一次、回收一次**；除非重複有新意，不要反覆解釋或補同義吐槽。
- 主歌、演出、旅行和過場不需逐動作完整記錄；只寫對故事或人物有影響的節點。
- 以「讀起來順、看得下去」為主，不機械追求字數，也不因過度精簡而刪掉真正有用的現場互動。

## 2. 敘事風格

- 台灣口語自然，能聽見人物聲音；避免機械式文青感、空泛哲理、硬塞金句。
- 幹話是人物特色，不是每段的收尾義務。允許沉默、一起看海、一起唱歌、呼吸與動作代替解釋。
- 少用「他很感動／這就是友情／原來成長就是……」等替讀者下結論的旁白。
- 具體感官細節只挑**能建立場景或推動情節的一兩筆**：如巨蛋低音震胸口、同步亮起的發光棒、電風扇吹動長髮；避免每次都逐一寫光、風、汗、聲浪。
- 用短的轉場句（例如「票要先弄到手。」）、場景切換與省略法，取代重複的準備／坐車／抵達流水帳。
- 不要用多個角色輪流替同一件事做評語；讓事件自己好笑。

## 3. 結構與情感

- 一章至少有可辨識的事件推進或人物狀態改變，不必強行營造重大衝突。
- 音樂章節避免每首都寫成同樣長度的高潮：有的歌負責回憶，有的歌負責演出主場，有的只需一句過場。
- 讓前章事物在後章自然回響：EP.01 一副耳機的〈夏夜晚風〉，到了 EP.05 成為兩人及全場的接唱；不必另寫解說。
- 有意義的台詞留在事件後面，由前面的行動支撐，不要在台詞後再補一長段議論。
- 真實音樂、地點、演出資訊需要考證時先核實；允許**小說化調整**，但不要把虛構喊麥或歌單寫成史實。
- 作者提供的歌曲文字可作創作素材，**不得單方面因「太多歌詞」而擅自刪減作者已決定保留的段落**；對外發布時另外檢查引用範圍及授權風險，將提示與作品修改分開處理，不要讓歌詞堆砌代替小說敘事。

## 4. 禁止復發的 AI 習慣

1. 不要為了「有代入感」就擴充成冗長逐字紀錄。
2. 不要每兩三句就塞一個「幹／靠北」或第三人跳出吐槽。
3. 不要在笑點剛成功後，再追加兩輪相同笑點的解釋。
4. 不要連續反覆描寫人物「瞪大眼、尖叫、唱很大聲、笑到彎腰」而沒有新發展。
5. 不要任意替作者控制的主角補關鍵回應、替作品設定年份、追加戀愛或重大事件。
6. 不要使用「不是……而是……」「我反而覺得」等假性反駁，換句話重述作者明明已經說過的意思。
7. 不要擅自修正已核定正文；上架／排版／網站工程時只做被授權的改動，保留現有 Git 修改、作品結構和人物設定。

## 5. 修稿前快速驗收（逐章）

- [ ] 本章有一條明確事件線與至少一次人物／關係的小變化。
- [ ] 角色的每句對白有推進、揭示或真正的新笑點。
- [ ] 相似的吐槽、相同感官描寫和重複心理解釋已合併。
- [ ] 一段音樂、一場旅程或一個日常橋段沒有被寫成流水帳。
- [ ] 主角仍有行動、說話與選擇，不只是站旁邊看配角表演。
- [ ] 前章細節、人物關係與時間線一致，未擅自定死年份。
- [ ] 結尾不用總結人生道理，也能留下清晰的畫面／餘韻。
- [ ] 若作品有正式母本，修訂差異與作者已確認的版本可追蹤；未經批准不直接上架。

## 6. EP.05 作為標準案例

**作者否定的版本：** 共創逐輪內容原樣串起，登場、飲水、接歌、反應、笑點都有多輪對話，作者明確說「太多贅字，看不下去」。

**作者接受的方向：** 保留搶票程式失敗／請假／同步亮棒／〈夏夜晚風〉呼應／〈夢醒時分〉接唱／加班安可／嘉豪錄音反轉／鹽酥雞碰杯；中間用有意義的轉場迅速前進。作者評語：「這版可以欸，看得下去」。

**記住的判準：** 短，不代表少情緒；長，不代表有代入感。讓讀者在該聽歌時聽歌、該笑時笑、該回到日常時直接切回去。

## 7. 和工程 Agent 協作的邊界

- 本檔是**寫作層規則**；網站已有的 `AGENTS.md`、`00_PROJECT/` 工程說明及正式正文檔，不得以本檔覆蓋。
- 建議經使用者核對目前 repo 後，將本檔作為獨立的寫作規則文件，由現有 `AGENTS.md` 加入一條參照；共創記憶另存獨立檔案，非授權不直接修改小說正文。
- 若作者請求「上架」，須先讀最新核准的 Markdown 正文，維持原意、角色與段落節奏；不得自動重寫已定稿內容。

## 8. EP.05 驗證後的「局部回收」工作法

- **先找已有鋪陳，少加新東西。** 例如車上推薦的歌、背包裡的講義、進場前問起的電風扇、現場錄影，都只需一到數句在後文自然回收。
- **保護收尾**：結尾既已形成笑點、友情約定和現實回歸，不要為求伏筆完整就新增老闆質問、感情糾紛或沉重寓意。
- **不用每個細節都有劇情回報**：只處理明顯影響連續性或能加強現有笑點的鋪陳。
- **前後動作要接得上**：例如錄影需要人物曾拿手機；拿手機拍攝與同時勾肩揮棒須有先後順序。
- **作者核准的簡潔版優先於舊共創原始逐字稿**：局部修稿不得順手恢復長篇過場和吐槽。
- **工程與編輯是不同權限**：上架時只依隨附的正式章節 Markdown 整合，不由 Codex 獨立改寫正文、剪歌詞或更改小說安可順序；原有 `AGENTS.md` 與 `00_PROJECT/` 規範保留並以增量方式參照本檔。
